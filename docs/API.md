# REST API мобильного приложения арендатора

Документация для разработчика мобильного приложения (ТЗ-01).
Серверная часть реализована по ТЗ-02, раздел 6.

- **Базовый URL (прод):** `https://bazar.zeastudio.su/api/v1`
- **Формат:** JSON, UTF-8. Загрузка чека — `multipart/form-data`.
- **Все суммы — строки** с двумя знаками после запятой: `"12000.00"`. Валюта — сом (KGS), в API не передаётся.
- **Даты** — ISO 8601 с часовым поясом (`2026-09-01` / `2026-09-01T10:30:00+06:00`). Часовой пояс системы — Asia/Bishkek.
- **Пагинация** — параметры `page` и `page_size` (по умолчанию 20, максимум 100).
- Все расчёты выполняет сервер. Приложение **только отображает** полученные значения и никогда не считает долг само.

## 1. Аутентификация

Вход — **только по ИНН**, без пароля (решение заказчика, ТЗ-00 раздел 8).

### POST /auth/login — вход

Без токена. Тело:

```json
{
  "inn": "20305199500123",
  "device_info": "iPhone 15, iOS 19.1, app 1.0.0",
  "consent_accepted": true,
  "pin": null
}
```

| Поле | Обязательно | Описание |
|---|---|---|
| `inn` | да | ИНН арендатора, строка |
| `device_info` | нет | Свободная строка об устройстве — попадает в журнал входов |
| `consent_accepted` | нет | `true` при первом входе, когда пользователь принял согласие на обработку ПДн. Дата и версия текста согласия фиксируются на сервере один раз |
| `pin` | нет | PIN-код. Нужен только если в `/app/config` `pin_login_enabled: true` и у арендатора установлен PIN |

Ответ `200`:

```json
{
  "token": "a1b2c3...40hex",
  "profile": {
    "full_name": "Асанова Гульмира",
    "inn": "20305199500123",
    "phone": "+996700111222",
    "status": "active",
    "language": "ru",
    "consent_accepted_at": "2026-08-25T10:00:00+06:00"
  }
}
```

Ошибки:

| Код | `code` | Когда |
|---|---|---|
| 400 | `login_failed` | ИНН не найден или арендатор в архиве. Текст одинаковый для обоих случаев — различать нельзя намеренно |
| 400 | `pin_required` | Включён режим PIN: повторите запрос с полем `pin` |
| 429 | `throttled` | Больше 10 попыток входа с одного IP/устройства за час |

**Токен:**
- Передаётся в каждом запросе: заголовок `Authorization: Token <token>`.
- **Не имеет срока истечения.** Отзывается при: выходе (`/auth/logout`), переводе арендатора в архив, действии администратора.
- На любой запрос может прийти `401` — это значит, токен отозван. Приложение должно очистить локальное состояние и показать экран входа. Повторный вход по ИНН — штатный сценарий.
- Статус `suspended` (приостановлен): вход и просмотр разрешены, но любые изменяющие запросы (подача заявки) вернут `403`.

### POST /auth/logout — выход

С токеном. Отзывает текущий токен. Тело опционально: `{"push_token": "..."}` — деактивирует и push-токен устройства. Ответ `200 {"detail": "ok"}`.

## 2. Конфигурация приложения

### GET /app/config — без токена

Запрашивать при старте приложения, до входа.

```json
{
  "min_app_version": "1.0.0",
  "contacts": "Администрация: +996 ...",
  "market_name": "Рынок ...",
  "reminder_days": [10, 5, 3, 0],
  "pin_login_enabled": false,
  "consent_version": "1.0"
}
```

`min_app_version` — если версия приложения ниже, показать экран «обновите приложение».
`pin_login_enabled` — включает поле PIN на экране входа.

## 3. Главный экран

### GET /me — профиль

```json
{"full_name": "...", "inn": "...", "phone": "...", "status": "active", "language": "ru"}
```

### GET /me/summary — сводка для главного экрана

Единственный источник цифр для главного экрана:

```json
{
  "debt": "12000.00",
  "overdue_amount": "0.00",
  "advance": "0.00",
  "amount_due": "12000.00",
  "next_due_date": "2026-09-30",
  "days_until_due": 12,
  "payment_status": "awaiting",
  "has_pending_claim": false,
  "tenant_status": "active"
}
```

| Поле | Описание |
|---|---|
| `debt` | Общий долг, включая начисления с ненаступившим сроком |
| `overdue_amount` | Просроченная часть долга (выделяется красным) |
| `advance` | Аванс (переплата), зачтётся в следующее начисление автоматически |
| `amount_due` | Остаток к доплате (= debt) |
| `next_due_date` | Ближайший срок оплаты, `null` если платить нечего |
| `days_until_due` | Дней до срока, `null` если платить нечего |
| `payment_status` | Статус для индикации: см. ниже |
| `has_pending_claim` | Есть заявка «на проверке» — показать соответствующий статус |
| `tenant_status` | `active` / `suspended`. При `suspended` — режим только просмотра |

`payment_status` (цветовая индикация, ТЗ-02 п. 4.6):

| Значение | Смысл | Рекомендуемый цвет |
|---|---|---|
| `no_debt` | Долга нет | зелёный |
| `awaiting` | Есть начисления, срок не близко | нейтральный |
| `due_soon` | До срока ≤ 3 дней | жёлтый |
| `overdue` | Срок прошёл | красный |

Пени и штрафы не начисляются никогда — просрочка влияет только на статус и уведомления.

## 4. Места и начисления

### GET /me/spots — список мест арендатора (без пагинации, массив)

```json
[{
  "id": 3, "code": "А-01", "building": "Корпус А", "spot_type": "container",
  "area_sqm": "12.50", "monthly_amount": "12000.00",
  "start_date": "2026-01-01", "photo": null
}]
```

### GET /me/spots/{id} — карточка места (тот же формат)

### GET /me/charges — начисления (пагинировано)

Параметры фильтра: `period=2026-09` (месяц), `spot=<id>`, `status`, `page`, `page_size`.

```json
{
  "count": 12, "next": null, "previous": null,
  "results": [{
    "id": 41, "period_year": 2026, "period_month": 9,
    "amount": "12000.00", "paid_amount": "5000.00", "remaining": "7000.00",
    "charged_date": "2026-09-01", "due_date": "2026-09-30",
    "status": "partial", "source": "auto", "comment": "", "spot_code": "А-01"
  }]
}
```

Статусы начисления (`status`):

| Значение | Отображение |
|---|---|
| `unpaid` | Не оплачено |
| `partial` | Оплачено частично — показать «Оплачено X из Y, осталось Z» |
| `paid` | Оплачено |
| `overdue` | Просрочено |
| `cancelled` | Отменено администрацией (в списках можно скрывать или показывать зачёркнутым) |

`source`: `auto` — ежемесячное, `manual` — разовое, `initial` — «Долг на начало работы Системы», `adjustment` — корректировка долга в плюс.

### GET /me/charges/{id} — детали начисления

Тот же объект + `allocations` — чем начисление погашалось:

```json
{
  "...": "...",
  "allocations": [
    {"id": 7, "amount": "5000.00", "kind": "payment", "payment_id": 12,
     "paid_at": "2026-09-05T14:00:00+06:00", "created_at": "..."}
  ]
}
```

`kind`: `payment` — платёж, `advance` — зачёт аванса, `adjustment` — корректировка администрации.

## 5. Оплата

Сценарий оплаты (ТЗ-00 п. 6.3): экран QR → пользователь платит в своём банковском приложении → возвращается → подаёт заявку с фото чека → ждёт подтверждения администратором. **Долг меняется только после подтверждения.**

### GET /payment-info — QR-код и инструкция

```json
{
  "qr_image": "https://bazar.zeastudio.su/media/qr/qr.png",
  "instruction": "Отсканируйте QR-код в приложении банка...",
  "market_name": "Рынок ..."
}
```

Язык инструкции — язык арендатора; заголовок `Accept-Language: ky` переключает на кыргызский. QR показывать крупно, дать сохранить скриншотом (FR-QR-04). `qr_image` доступен без токена.

### POST /payment-claims — подача заявки об оплате

`multipart/form-data`:

| Поле | Обязательно | Ограничения |
|---|---|---|
| `declared_amount` | да | От `1.00` до (текущий долг + 100 000) |
| `receipt_image` | да | **JPG или PNG, до 10 МБ.** Проверяется сигнатура файла, а не расширение |
| `idempotency_key` | да | Уникальная строка ≤64 симв. Генерировать UUID **при создании заявки на клиенте** и переиспользовать при ретраях |
| `comment` | нет | Комментарий арендатора |

Ответ `201`:

```json
{"id": 17, "declared_amount": "12000.00", "status": "pending",
 "submitted_at": "...", "reviewed_at": null, "reject_reason": "", "comment": ""}
```

Повторный POST с тем же `idempotency_key` вернёт **ту же заявку** (код 201, дубль не создастся) — безопасно ретраить при обрыве сети.

Ошибки: `400` — сумма вне лимитов или файл не JPG/PNG; `413` — файл больше 10 МБ; `403` — арендатор приостановлен.

### POST /payment-claims/{id}/withdraw — отозвать заявку

Работает только пока заявка `pending`. Ответ — заявка со `status: "withdrawn"`. Если администратор уже обработал — `409`.

Статусы заявки:

| Статус | Смысл | Что показать |
|---|---|---|
| `pending` | На проверке | «Ожидает подтверждения», кнопка «Отозвать» |
| `confirmed` | Подтверждена | Платёж проведён, долг обновлён |
| `rejected` | Отклонена | Причину из `reject_reason` + кнопку «Подать заново» |
| `withdrawn` | Отозвана арендатором | — |

## 6. История операций

### GET /me/payments — единая лента (пагинировано)

Каждый элемент имеет `type` и **строковый** `id` вида `"claim-17"`, `"payment-12"`, `"adjustment-3"`:

```json
{
  "count": 3, "next": null, "previous": null,
  "results": [
    {"id": "claim-17", "type": "claim", "date": "...", "amount": "12000.00",
     "status": "confirmed", "reject_reason": "", "comment": ""},
    {"id": "payment-12", "type": "payment", "date": "...", "amount": "5000.00",
     "status": "active", "comment": "Внесён администрацией"},
    {"id": "adjustment-3", "type": "adjustment", "date": "...", "amount": "-1000.00",
     "status": "active", "reason": "Скидка по договорённости"}
  ]
}
```

- `type: "claim"` — заявки арендатора (все статусы).
- `type: "payment"` — платежи, внесённые администрацией напрямую (платежи по заявкам отдельной строкой не дублируются — их видно по подтверждённой заявке).
- `type: "adjustment"` — корректировки долга администрацией; сумма бывает отрицательной; обязательно показывать `reason` (FR-PM-15).

### GET /me/payments/{id} — детали (id строковый: `claim-17`)

Для заявки дополнительно: `receipt_url` (ссылка на чек), `accepted_amount` — сумма, фактически зачтённая администратором (может отличаться от заявленной).

### GET /me/receipts/{claim_id} — фотография чека

Отдаёт бинарное изображение, **требует токен** (заголовок Authorization, как у всех запросов). Прямая ссылка `/media/...` не работает — грузить только через этот эндпоинт.

## 7. Уведомления и push

### GET /me/notifications — лента (пагинировано)

```json
{"results": [{
  "id": 5, "code": "reminder_3", "title": "Срок оплаты приближается",
  "body": "Гульмира, до срока оплаты аренды осталось 3 дня...",
  "payload": {"event": "reminder", "days": 3},
  "created_at": "...", "read_at": null
}]}
```

Лента содержит **все** уведомления, даже если push не доставился, — она первична, push вторичен.

### POST /me/notifications/read — отметить прочитанными

Тело: `{"ids": [5, 6]}`. Ответ: `{"updated": 2}`.

### POST /me/devices — регистрация push-токена

Вызывать после входа и при каждом обновлении FCM-токена:

```json
{"push_token": "<fcm token>", "platform": "android", "app_version": "1.0.0", "locale": "ru"}
```

`platform`: `android` | `ios`. Ответ `201 {"id": ...}`. Повторная отправка того же токена — upsert, не ошибка.

Push идут через **Firebase Cloud Messaging** (единый механизм для Android и iOS). В `data` push-сообщения приходит `payload` уведомления — коды событий для навигации:

| `code` | Событие | Куда вести по тапу |
|---|---|---|
| `charge_created` | Новое начисление | Главный экран |
| `reminder_10` / `reminder_5` / `reminder_3` / `reminder_0` | Напоминание о сроке | Главный экран / экран оплаты |
| `claim_confirmed` | Оплата подтверждена, долг погашен | История |
| `claim_confirmed_partial` | Оплата подтверждена, есть остаток | Главный экран |
| `claim_rejected` | Заявка отклонена (причина в тексте) | Экран заявки |
| `overdue` | Просрочка | Экран оплаты |
| `announcement` | Объявление администрации | Лента уведомлений |

Язык уведомления = язык арендатора (`/me/settings`), не язык устройства.

## 9. Ошибки, лимиты, статусы

Единый формат любой ошибки:

```json
{"code": "validation_error", "message": "Ошибка валидации.", "details": {"declared_amount": ["..."]}}
```

Заголовок `Accept-Language: ru|ky` управляет языком сообщений.

| HTTP | `code` | Обработка в приложении |
|---|---|---|
| 400 | `validation_error`, `login_failed`, `pin_required` | Показать `message` / подсветить поля из `details` |
| 401 | `not_authenticated` | Токен отозван → экран входа |
| 403 | `forbidden` | Аккаунт приостановлен: режим просмотра |
| 404 | `not_found` | Объект не существует **или принадлежит другому арендатору** — сервер намеренно не различает |
| 409 | `conflict` | Заявка уже обработана/отозвана → перезапросить её состояние |
| 413 | `file_too_large` | Чек больше 10 МБ → предложить пересжать |
| 429 | `throttled` | Подождать и повторить (вход: лимит 10 попыток/час) |
| 500 | `internal_error` | «Попробуйте позже», подробностей сервер не отдаёт |

Лимиты: вход — 10 попыток/час с IP или устройства; остальные методы — 100 запросов/мин на арендатора.

## 10. Чек-лист интеграции

1. Старт → `GET /app/config` (версия, PIN, контакты).
2. Вход → `POST /auth/login` (при первом входе `consent_accepted: true` после показа текста согласия).
3. После входа → `POST /me/devices` (FCM-токен), `GET /me/summary`.
4. Главный экран — только из `/me/summary`; формат суммы «12 500 сом», даты ДД.ММ.ГГГГ.
5. Оплата: `GET /payment-info` → банк → `POST /payment-claims` (UUID как `idempotency_key`).
6. Любой `401` → выход на экран входа. `tenant_status: "suspended"` → скрыть кнопку оплаты.
7. Пока `has_pending_claim: true` — показывать «заявка на проверке», долг не менять.

Интерактивная схема (Swagger UI) доступна на dev-контуре: `/api/docs/`.
Вопросы по серверу — issues в репозитории https://github.com/Nurbolottop/Bazar.
