# Bazar — учёт аренды торговых мест рынка

Серверная часть и REST API системы учёта аренды торговых мест: реестр мест и
арендаторов, автоматические ежемесячные начисления, заявки об оплате с фото
чека, подтверждение оплат администрацией, долги, аванс, уведомления.

Реализуется по ТЗ:

- `ТЗ-00_Общее_техническое_задание.docx` — система в целом, роли, бизнес-процессы
- `ТЗ-02_Серверная_часть_и_админ-панель.docx` — Django, модель данных, API, панель

**Стек:** Python 3.11 · Django 5.2 · Django REST Framework · PostgreSQL 16 ·
drf-spectacular · Firebase Admin SDK · Docker Compose

---

## Быстрый старт

```bash
# .env уже сгенерирован (scripts/init-project.sh bazar); если нет:
./scripts/init-project.sh bazar --force

docker compose up --build
```

- Приложение: http://127.0.0.1:8081 (порт — `WEB_PORT` из `.env`)
- Проверка живости: `GET /health/`
- Документация API (только dev): http://127.0.0.1:8081/api/docs/
- Служебная админка Django (инструмент разработчика, НЕ рабочее место
  администрации — ТЗ-02 п. 2.3): `/django-admin/`

Создать администратора:

```bash
docker compose exec web python manage.py createsuperuser
```

Тесты (50 контрольных сценариев по п. 12.2 ТЗ-02):

```bash
docker compose run --rm web python manage.py test
```

## Структура

```
app/
├── core/                  # settings (base/dev/prod), urls, wsgi
└── apps/
    ├── core/              # SystemSettings, AuditLog, деньги (Decimal), health
    ├── accounts/          # вход по ИНН, токены, устройства, журнал входов
    ├── catalog/           # корпуса, торговые места
    ├── tenants/           # арендаторы, привязка мест, суммы аренды
    ├── billing/           # начисления, прогон начислений (run_billing)
    ├── payments/          # заявки, платежи, распределение, аванс, корректировки
    ├── notifications/     # шаблоны, лента, push, объявления, напоминания
    └── reports/           # отчёты и выгрузка в Excel (в работе)
```

Вся бизнес-логика — в `services.py` каждого приложения (ТЗ-02 п. 2.2).
Views и API-сериализаторы правил расчёта не содержат — веб-панель и API
вызывают один и тот же сервисный слой.

## Ключевые правила предметной области

- **Две даты**: `billing_day` (по умолчанию 1-е, создаётся начисление) всегда
  строго раньше `payment_day` (по умолчанию 30-е, срок оплаты). Настройка с
  нарушением порядка отклоняется; в коротких месяцах даты усекаются к
  последнему дню без схлопывания (ТЗ-02 п. 4.1–4.2).
- **Деньги** — только `DecimalField(12, 2)`, округление ROUND_HALF_UP, float запрещён.
- **Финансовые записи не удаляются** — только отмена/сторно с причиной и записью
  в `AuditLog`.
- **Платёж гасит начисления** от раннего `due_date` к позднему; переплата — в
  аванс, аванс автоматически зачитывается в следующее начисление со ссылкой на
  исходный платёж (`PaymentAllocation`, kind=advance).
- **Долг** = сумма непогашенных остатков всех неотменённых начислений (включая
  будущие сроки); просроченная часть считается отдельно. Долг не бывает
  отрицательным. `TenantBalance` — производная, пересчитывается в транзакции.
- **Вход арендатора по одному ИНН** — решение Заказчика (ТЗ-00 раздел 8):
  лимит 10 попыток/час с IP или устройства, все попытки в `TenantLoginLog`,
  токен — SHA-256-хеш в базе, PIN-код реализован и выключен настройкой
  `pin_login_enabled`.

## Фоновые задачи (cron)

Management-команды с файловой блокировкой от параллельного запуска
(ТЗ-02 раздел 8), время сервера — Asia/Bishkek:

```cron
30 0 * * *   docker compose -f /path/docker-compose.prod.yml exec -T web python manage.py run_billing
50 0 * * *   docker compose -f /path/docker-compose.prod.yml exec -T web python manage.py update_charge_statuses
0 9 * * *    docker compose -f /path/docker-compose.prod.yml exec -T web python manage.py send_reminders
*/10 * * * * docker compose -f /path/docker-compose.prod.yml exec -T web python manage.py send_pending_notifications
0 4 * * *    docker compose -f /path/docker-compose.prod.yml exec -T web python manage.py cleanup_tokens
0 3 * * *    /path/scripts/backup.sh   # pg_dump + файлы (добавить при деплое)
```

`run_billing --dry-run [--date YYYY-MM-DD]` — предварительный просмотр прогона
без записи в базу (FR-CH-07).

## REST API

Базовый путь `/api/v1/`, аутентификация `Authorization: Token <ключ>`,
суммы — строки с двумя знаками, ошибки — `{"code", "message", "details"}`.
Полный перечень методов — ТЗ-02 п. 6.2; схема OpenAPI генерируется
drf-spectacular (`/api/schema/`, dev).
